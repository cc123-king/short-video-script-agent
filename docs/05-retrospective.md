# 复盘与后续

## 最难的问题

本阶段最关键的问题是让“模型说检查通过”和“程序确有同版本证据”一致。只在提示中要求不要编造不足以保障交付，因此引入受控事实表达、基于内容哈希的版本，以及由代码校验的完成条件。

第二个问题是时长修改是否实质改变内容。估算不能直接信任模型填写总时长，要从旁白、屏幕文字和画面停留重新计算；修正后保存新旧版本便于核对。

接入时暴露了配置校验和失败汇总的不足：错误接口/不完整 Key 导致模型调用未开始；评估器还曾对空版本抛异常。这些实际失败促成了输入检查和失败记录的改进。

## 技术收获

- 模型动态选择与确定性约束承担不同职责：模型决定下一步，代码核对事实、结果和边界。
- 事实 ID 存在不代表它支持某句话；需要核对实际引用文字与来源。
- 失败场景要从工具端注入，再观察模型动作，不能先写好成功日志。
- 原型采用核准表达易验证，但自由创作能力有限，需要明确这一取舍。

本节是 AI 对实现过程的技术整理，不能替代作答者个人学习记录。个人理解、实际验证与收获待完成后补充。
